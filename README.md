# 星轨档案库 · Stellar Archive

> 玩家自制的《崩坏：星穹铁道》静态战斗数据档案库。  
> **非官方工具，与 miHoYo / HoYoverse 无任何隶属、合作或授权关系。**  
> 测试服、预下载埋包与未实机内容随时可能改动、推迟或直接作废，不代表最终效果。

这是一个纯静态、只读、可离线的数据档案 PWA。它把正式服、测试服、未实机与已废弃内容按信任等级分区存放，便于回溯历代版本、比对角色快照、查阅高难关卡轮换，也可以在断网时继续浏览已归档的数据包。

## 能做什么

- **角色档案**：93 名已上线角色，Lv.80 基础面板、技能倍率、星魂与行迹、版本快照链；成长曲线为按满级面板反推的拟合曲线。
- **版本回溯与对比**：角色详情可切换历史快照；两个版本并排查看面板 / 技能差异，涨跌用红绿标注。
- **历代关卡**：100 期轮换档案（混沌回忆 42、虚构叙事 27、末日幻影 21、异相仲裁 10），名称、起止日期、环境效果与敌方编成按 BWIKI 逐期整理。
  - 异相仲裁自 3.6 起归档：3 名骑士 + 1 个王棋、3 支不重复队伍、每关 6 轮行动值、骑士通关削弱王棋、无星琼奖励。
- **光锥 / 遗器 / 敌人**：结构演示目录；关卡页只以名称记录敌人，不链接到演示数值。
- **检索与筛选**：全站搜索（未实机内容默认隔离）、角色散点图 / 雷达、关卡模式与版本筛选。
- **多角色对比**：2–4 名角色并排，雷达、数据表与技能小图。
- **关注清单**：仅写入浏览器 `localStorage`，不是账号数据。
- **导出**：单条 JSON、角色全部快照 JSON、CSV、当前图表 PNG。
- **PWA / 离线**：安装到桌面，Service Worker 预缓存应用外壳；数据包装入 IndexedDB 后可离线回溯。
- **响应式与可访问性**：桌面 / 平板 / 手机布局，图表支持键盘聚焦、数据表视图与 `aria-label`。

## 明确不提供

本档案库是只读资料库，不包含以下功能：

- 用户数据录入 / 编辑、账号注册或登录
- 队伍模拟、DPS / 伤害计算、行动轴模拟
- 遗器副词条输入与词条评分
- 评论、发帖、排行或公开主页
- 读取游戏账号、抓包或任何游戏客户端交互

## 数据与信任等级

| 等级 | 来源 | 全局搜索 | 同人图 | 可信说明 |
| --- | --- | --- | --- | --- |
| 正式 | 正式服稳定版本 | 默认包含 | 最多 2 幅，强制标注 | 永久快照，可版本回溯 |
| 测试服 | 测试服整理包 | 默认隔离 | 不挂载 | 上线后自动归档 |
| 未实机 | 预下载 / 埋包 | 默认隔离 | 不挂载 | 随时作废 |
| 已废弃 | 历史失效内容 | 不包含 | 不挂载 | 仅作考据留存 |

未实机条目不会进入正式快照链，也不会挂载同人图。全局搜索需要手动开启「包含测试服 / 未实机」后才会显示，且保留强警示标签。

### 数据口径说明

- 角色满级基础面板、技能倍率、星魂与行迹按**米游社 Wiki** 的角色页面整理；尚未实装或不在 Wiki 内的角色不会被补写。
- 关卡名称、起止日期、环境效果与敌方编成按 **BWIKI 崩坏：星穹铁道 Wiki** 的历代轮换页面逐期录入；社区页面缺失的编成保持「未收录」，不作推测补写。早期 8 期混沌回忆只保留名称与环境效果，末日幻影页面通常只列首领名称、没有逐波编成，页面都会按原样标注。
- 角色成长曲线为按 Lv.80 面板反推的**拟合曲线**，不是逐级实测数据；速度按游戏规则不随等级成长。
- 当前档案只保留角色上线时的满级快照，没有逐版本平衡调整记录，因此版本对比通常不会显示数值差异。
- 测试服 / 未实机专区当前为空，只保留隔离与警示机制，不使用虚构条目填充。
- 光锥、遗器与敌人目录仍是**结构演示**，不冒充完整数值库；敌人的生命 / 防御为演示拟合值。
- 同人画廊中的图片全部为程序生成的占位插画，画师、授权与来源均为占位信息；未使用任何官方美术资源。

## 运行方式

项目为原生 HTML / CSS / JavaScript（ES Modules），**无需构建、无第三方依赖**。由于使用 Service Worker 与 IndexedDB，需要通过 HTTP 静态服务器打开，不能直接双击 `index.html`。

```bash
# 任选其一，在项目根目录执行
python -m http.server 8765
# 或
npx serve -l 8765
```

然后访问：

```text
http://127.0.0.1:8765/
```

首次打开会显示免责声明。联网打开一次后，Service Worker 会缓存应用外壳，可尝试离线刷新；在「版本更新中心」安装数据包后，对应版本快照会写入本机 IndexedDB。

### 日常打开

Windows 下直接双击项目根目录的 `启动星轨档案库.bat`：脚本会自动启动本地服务器并打开浏览器。**使用期间不要关闭那个命令行窗口**；关闭窗口即停止服务。若服务器已在运行，脚本只会打开浏览器。

固定使用 `http://127.0.0.1:8765/`，不要换成 `localhost`，两者在浏览器中属于不同站点，关注清单与 IndexedDB 数据不会互通。

### 打开后显示的是旧内容？

页面由 Service Worker 缓存应用外壳，更新后第一次加载可能仍在用旧缓存。底部页脚会标出当前版本（例如 `App v1.2.0 · 数据 v4.6.0`），可据此判断是否为新版。若版本号偏旧：

1. 连续按两次 `F5`（或一次 `Ctrl + F5`）强制刷新；
2. 仍然不行时，进入「版本更新中心」，点「强制刷新应用」——它会注销 Service Worker、清除应用外壳缓存并重新加载，本机已安装的数据包不受影响。

也可以首次打开后点击右上角「安装应用」，把档案库装成桌面 / 开始菜单应用；已缓存内容可离线查看，但数据包更新和首次加载仍需要本地服务器运行。

## 目录结构

```text
.
├── index.html                 # 应用入口
├── manifest.webmanifest       # PWA 清单
├── sw.js                      # Service Worker（外壳预缓存 + 离线回退）
├── css/style.css              # 深空主题与全部页面样式
├── assets/icons/              # 程序生成的图标（SVG / PNG / maskable）
├── js/
│   ├── app.js                 # 路由、壳层、全局搜索、PWA 注册
│   ├── charts.js              # 零依赖 SVG 图表引擎
│   ├── ui.js / store.js       # 通用 UI、IndexedDB / localStorage
│   ├── assets.js              # 程序化占位图生成
│   ├── export.js              # JSON / CSV / PNG 导出
│   ├── data/                  # 角色、光锥、遗器、敌人、关卡、版本数据
│   └── pages/                 # 各路由页面
└── tools/                     # 本地验证与截图脚本（开发辅助）
```

## 本地验证脚本

`tools/verify.mjs` 使用 Playwright（Chrome 通道）做冒烟验证，覆盖免责声明、主要路由、搜索、关注 / 对比托盘、数据包安装、JSON / PNG 下载、Service Worker、离线刷新与移动端布局。

```bash
# 先启动静态服务器（默认 8765 端口）
python -m http.server 8765
# 另一个终端
node tools/verify.mjs
```

脚本依赖本机 Playwright 安装路径；如环境不同，请调整脚本顶部的 `import(...)` 路径。截图输出在 `tools/shots/`。
